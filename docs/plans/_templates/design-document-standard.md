# 설계 문서(design.md) 작성 표준

## 필수 섹션 구조

design.md는 아래 9개 섹션을 순서대로 포함해야 한다. 최소 1~6번은 필수.

| # | 섹션 | 필수 | 핵심 내용 |
|---|------|:----:|----------|
| 1 | 시스템 개요 | ✓ | 목적 2~3문장 + 기술 스택 표 |
| 2 | 아키텍처 | ✓ | 3가지 관점: 배포 구조, 정적 구조, 동적 흐름 |
| 3 | 주요 엔터티 | ✓ | 데이터 모델 표, 상태, 스키마, 설정, 예외 |
| 4 | 주요 기능 상세 | ✓ | 기능별: 엔드포인트, JSON 예시, 흐름, 알고리즘 |
| 5 | 시퀀스 다이어그램 | ✓ | Mermaid/ASCII, 실제 파일/클래스명 사용 |
| 6 | 핵심 설계 결정 | ✓ | 결정별: 무엇을 + 왜 + 코드 예시 |
| 7 | API 요약 | - | 전체 엔드포인트 표 |
| 8 | 테스트 구조 | - | 테스트 파일별 표 + 격리 전략 |
| 9 | 확장 포인트 | - | 미구현 기능의 추가 방법 |

## 작성 원칙

- 도해만 그리지 않음 → 반드시 구체적 설명(표/산문) 동반
- ASCII 도해 기본, Mermaid는 복잡한 시퀀스에만
- 실제 파일명/함수명/클래스명 사용 (추상적 이름 금지)
- 요청/응답은 실제 JSON 예시 포함
